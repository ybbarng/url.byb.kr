# 요구사항 정의서

## 1. 프로젝트 개요

### 1.1 배경

서비스 개발 및 테스트 과정에서 다양한 환경(dev, staging, production 등)의 URL을 수동으로 조합하는 것은
번거롭고 오류가 발생하기 쉽습니다. 특히 URL이 다음과 같은 다수의 구성요소로 이루어진 경우:

```
https://blog-staging.example.com/posts/hello-world?lang=ko
https://api-dev.example.com/v2/users/42?verbose=true
https://tracker.example.com/frontend/web-app/issues/101?view=board
http://localhost:5173/admin/dashboard
```

- **서브도메인**: 배포 환경 등을 나타냄 (`blog-staging`, `api-dev`, `tracker` 등)
- **도메인**: 서비스 도메인 (`example.com`, `localhost:5173` 등)
- **경로**: 정적 세그먼트(`/posts/`, `/issues/`)와 동적 세그먼트(`hello-world`, `42`)의 조합. 동적 세그먼트가 여러 개일 수도 있음 (`/frontend/web-app/issues/101`)
- **쿼리 파라미터**: 동작 옵션이나 부가 정보 (`lang=ko`, `verbose=true` 등)

이러한 구성요소들은 시나리오마다 달라지며, 매번 수동으로 조합하는 것은 비효율적입니다.

### 1.2 목표

**URL Kit**은 URL의 각 구성요소를 이름 기반으로 관리하고,
시각적으로 조합하여 빌드 및 열기를 제공하는 웹 도구입니다.

- 서비스 주소: `https://url.byb.kr`
- 모든 데이터는 브라우저 로컬(IndexedDB)에 저장하여 외부 유출을 방지합니다.

### 1.3 대상 사용자

- 서비스 개발자 (프론트엔드, 백엔드)
- QA 엔지니어
- PM/PO 등 서비스 확인이 필요한 인원

## 2. 핵심 개념

### 2.1 사이트 (Site)

URL 템플릿의 최상위 단위입니다. 사용자가 직접 이름을 부여하여 관리합니다.
도메인이 아닌 **사용자가 지정한 이름**이 식별자 역할을 합니다.

> 예: localhost 환경에서는 서로 다른 서비스가 같은 `localhost:3000`을 사용할 수 있으므로,
> 도메인만으로는 사이트를 구별할 수 없습니다.

### 2.2 URL 구성요소

하나의 사이트는 다음 구성요소들의 템플릿을 가집니다:

| 구성요소 | 설명 | 예시 |
|----------|------|------|
| 프로토콜 | `http` 또는 `https` | `https` |
| 서브도메인 옵션 | 선택 가능한 서브도메인 목록 | `tracker-dev`, `tracker-staging`, `tracker` |
| 도메인 | 기본 도메인 | `example.com` |
| 경로 세그먼트 | 정적 또는 동적 경로 조각들의 순서 목록 | `issues` (정적), `{team}` (동적), `{issueId}` (동적) |
| 쿼리 파라미터 | 키-값 쌍, 미리 정의된 옵션 가능 | `view` = `board` / `list` |

### 2.3 경로 세그먼트 (Path Segment)

경로는 여러 세그먼트의 연결로 구성됩니다:

- **정적 세그먼트**: 고정 값 (예: `issues`, `v2`)
- **동적 세그먼트**: 이름이 부여된 변수로, 사용 시 값을 선택/입력 (예: `{team}`, `{issueId}`)
  - 동적 세그먼트는 미리 정의된 옵션 목록을 가질 수 있음
  - 하나의 경로에 동적 세그먼트가 여러 개 포함될 수 있음 (예: `/{team}/{project}/issues/{issueId}`)

### 2.4 쿼리 파라미터 템플릿 (Query Parameter Template)

쿼리 파라미터도 미리 정의된 옵션을 가질 수 있습니다:

- 키 이름 (예: `view`)
- 표시 이름 (예: `보기 방식`)
- 미리 정의된 값 옵션들 (이름-값 쌍)
- 또는 자유 입력

### 2.5 프리셋 (Preset)

특정 사이트에 대해 구성요소 선택을 완료한 조합을 저장한 것입니다.
프리셋을 선택하면 바로 URL을 빌드하고 열 수 있습니다.

### 2.6 즐겨찾기 (Favorite)

프리셋 중 자주 사용하는 것을 즐겨찾기로 지정하면,
홈 화면에서 바로 접근하여 URL을 열 수 있습니다.

| ID | 요구사항 | 우선순위 |

## 4. 비기능 요구사항

### 4.1 데이터 저장

- 모든 데이터는 브라우저 **IndexedDB**에 저장합니다.
- 서버로 데이터를 전송하지 않습니다.
- 데이터 스키마 버전 관리를 통해 마이그레이션을 지원합니다.

### 4.2 UI/UX

- **반응형 디자인**: 모바일, 태블릿, 데스크톱 지원
- **다크 모드**: 시스템 설정에 따른 자동 전환 + 수동 토글
- **접근성**: 키보드 네비게이션, 적절한 ARIA 속성
- **피드백**: 복사 완료, 저장 완료 등 사용자 액션에 대한 시각적 피드백

### 4.3 성능

- 정적 사이트(SSG)로 빌드하여 빠른 초기 로드
- IndexedDB 접근은 비동기로 처리하여 UI 블로킹 방지

### 4.4 보안

- 외부 API 호출 없음 (순수 클라이언트 사이드)
- 민감한 정보(사용자 파라미터 등)는 로컬에만 저장
- XSS 방지를 위한 URL 인코딩 처리

## 5. 사용자 시나리오

### 시나리오 1: 새 사이트 등록 (다중 동적 경로)

1. 사용자가 "사이트 관리" 페이지에서 "새 사이트" 클릭
2. 사이트 이름 입력: `Issue Tracker`
3. 프로토콜 선택: `https`
4. 도메인 입력: `example.com`
5. 서브도메인 옵션 추가:
   - `tracker-dev` (표시 이름: "개발")
   - `tracker-staging` (표시 이름: "스테이징")
   - `tracker` (표시 이름: "프로덕션")
6. 경로 세그먼트 추가:
   - `+` 버튼 → 동적: 이름 `팀`, 옵션들:
     - `프론트엔드` → `frontend`
     - `백엔드` → `backend`
     - `모바일` → `mobile`
   - `+` 버튼 → 동적: 이름 `프로젝트`, 옵션들:
     - `웹 앱` → `web-app`
     - `API 서버` → `api-server`
   - `+` 버튼 → 정적: `issues`
   - `+` 버튼 → 동적: 이름 `이슈 번호`, 옵션들:
     - `로그인 버그` → `101`
     - `성능 개선` → `205`
7. 쿼리 파라미터 추가:
   - 키: `view`, 표시 이름: `보기 방식`, 옵션들:
     - `보드` → `board`
     - `리스트` → `list`
   - 키: `assignee`, 표시 이름: `담당자`, 옵션들:
     - `나` → `me`
     - `전체` → `all`

### 시나리오 2: URL 빌드 및 열기

1. URL 빌더 페이지에서 사이트 `Issue Tracker` 선택
2. 서브도메인: `tracker-staging` 선택
3. 경로 - 팀: `프론트엔드` (frontend) 선택
4. 경로 - 프로젝트: `웹 앱` (web-app) 선택
5. 경로 - 이슈 번호: `로그인 버그` (101) 선택
6. 쿼리 - 보기 방식: `보드` (board) 선택
7. 미리보기: `https://tracker-staging.example.com/frontend/web-app/issues/101?view=board`
8. "열기" 클릭 → 새 탭에서 URL 열림
9. 또는 "복사" 클릭 → 클립보드에 URL 복사

### 시나리오 3: 프리셋 저장 및 즐겨찾기

1. 시나리오 2의 상태에서 "프리셋 저장" 클릭
2. 프리셋 이름 입력: `FE 웹앱 로그인버그 보드뷰`
3. 저장 완료
4. 프리셋 목록에서 별표(즐겨찾기) 클릭
5. 홈 화면에서 즐겨찾기로 표시됨
6. 즐겨찾기 클릭 → 바로 URL 열기

### 시나리오 4: localhost 개발 환경

1. 새 사이트 생성: 이름 `Issue Tracker 로컬`
2. 프로토콜: `http`
3. 도메인: `localhost:3000`
4. 서브도메인: (없음)
5. 경로 세그먼트: 시나리오 1과 동일하게 추가
6. URL 빌드: `http://localhost:3000/frontend/web-app/issues/101?view=board`

## 6. 데이터 모델 (개요)

```
Site
├── id: string (UUID)
├── name: string
├── protocol: "http" | "https"
├── domain: string
├── subdomains: SubdomainOption[]
│   ├── id: string
│   ├── label: string (표시 이름)
│   └── value: string (실제 서브도메인)
├── pathSegments: PathSegment[]
│   ├── id: string
│   ├── type: "static" | "dynamic"
│   ├── label: string (표시 이름)
│   ├── value?: string (정적일 때 고정 값)
│   └── options?: SegmentOption[] (동적일 때)
│       ├── id: string
│       ├── label: string
│       └── value: string
├── queryParams: QueryParamTemplate[]
│   ├── id: string
│   ├── key: string (파라미터 키)
│   ├── label: string (표시 이름)
│   └── options?: ParamOption[]
│       ├── id: string
│       ├── label: string
│       └── value: string
├── createdAt: Date
└── updatedAt: Date

Preset
├── id: string (UUID)
├── siteId: string (Site 참조)
├── name: string
├── selectedSubdomainId: string | null
├── selectedPathValues: Record<segmentId, optionId | string>
├── selectedQueryValues: Record<paramId, optionId | string>
├── isFavorite: boolean
├── createdAt: Date
└── updatedAt: Date
```

## 7. 페이지 구성

| 경로 | 페이지 | 설명 |
|------|--------|------|
| `/` | 홈 | 즐겨찾기, 사이트 목록 바로가기 |
| `/sites` | 사이트 목록 | 등록된 사이트 목록 조회 |
| `/sites/new` | 사이트 생성 | 새 사이트 등록 폼 |
| `/sites/edit?id=xxx` | 사이트 수정 | 사이트 정보 수정 |
| `/builder` | URL 빌더 | URL 조합 및 빌드 |
| `/builder?siteId=xxx` | URL 빌더 (사이트 선택됨) | 특정 사이트로 빌더 진입 |
| `/presets` | 프리셋 목록 | 저장된 프리셋 관리 |
